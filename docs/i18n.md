# Guia de i18n — como adicionar ou corrigir traduções

O FreshBeat fala **pt-BR** (base/fallback), **en-US**, **ja-JP** e **es-ES** — no bot e no site. Este guia cobre os dois sistemas (eles são separados de propósito).

## Regras fixas

- **Nomes de comandos nunca são traduzidos** (`/playingnow` é `/playingnow` em qualquer idioma). Só descrições e respostas são localizadas.
- Placeholders usam `{{nomeDaVariavel}}` e devem ser **idênticos nos 4 idiomas** (testes garantem isso).
- Nunca concatene strings traduzidas para montar frases — use sempre uma chave com placeholders.

## Bot (`packages/i18n`)

1. No código, declare a mensagem com o texto pt-BR inline:

   ```ts
   msg({ key: 'playingnow.listening_now', value: '🎧 Ouvindo agora' })
   ```

   O `value` pt-BR é o fallback final — a feature funciona em pt-BR antes de qualquer tradução.

2. Adicione a chave aos 4 catálogos em `packages/i18n/src/locales/` (`pt-BR.ts`, `en-US.ts`, `ja-JP.ts`, `es-ES.ts`). Os catálogos não-base são tipados como `Record<MessageKey, string>` derivado da base — **o type-check falha se faltar chave**.

3. Rode `npm run verify` — os testes de i18n checam paridade de chaves e placeholders.

## Site (`apps/web/lib/i18n.ts`)

O site tem catálogos próprios no mesmo padrão (pt-BR tipado como base, os demais como `Record<WebMessageKey, string>`). Use `t(locale, 'chave', { var: valor })`. O locale vem do segmento `/[locale]` das rotas ou do `Accept-Language` (fluxos fora do prefixo, como o OAuth).

**Exceção consciente:** as descrições de comandos exibidas na landing são lidas do catálogo do **bot** via `getCatalog(locale)` — fonte única, sem duplicação.

## Fluxo de tradução

As traduções vivem **diretamente no repositório** — não usamos ferramenta externa (o Crowdin foi removido do projeto). Para corrigir ou adicionar uma tradução, edite os catálogos e abra PR: o type-check (chave faltando vira erro de compilação) e os testes de paridade (placeholders `{{var}}` idênticos) garantem a consistência.

## Dicas de tradução

- **ja-JP:** mantenha os emojis e a formatação HTML (`<b>`, `<code>`) intactos; a partícula など ajuda em listas.
- **es-ES:** use "tú" (tom informal, coerente com o pt-BR).
- **en-US:** cuidado com apóstrofos — prefira strings com aspas duplas no TS.
- Em dúvida, copie o tom do pt-BR: informal, direto e com emoji no final quando couber.
